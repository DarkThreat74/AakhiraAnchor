Fix iOS PWA display — safe-area insets, standalone height, overscroll bounce

On iOS, when Waqt is installed to the home screen (standalone PWA), the
app renders full-bleed with no Safari chrome. The status bar overlays
content, the Dynamic Island/notch eats ~59px at the top, and the home
indicator eats ~34px at the bottom. Without safe-area insets, the top
bar, back button, and nav links were hidden under the notch, and the
bottom nav was under the home indicator.

Research via Context7 (Next.js PWA docs) and Agent Reach/Exa (real-world
iOS PWA issues from GitHub PRs and Ionic issues) confirmed:
- env(safe-area-inset-top) is ~59px in standalone (vs ~8px in Safari)
- env(safe-area-inset-bottom) is ~34px in standalone
- 100dvh can be wrong on cold start in standalone; 100vh is correct
- apple-mobile-web-app-status-bar-style: black-translucent is the only
  way to get true fullscreen on iOS
- overscroll-behavior: none prevents the rubber-band bounce

Fixes:
1. globals.css: Added @media (display-mode: standalone) block that
   switches html height to 100vh and disables overscroll-behavior on
   html+body (prevents iOS rubber-band bounce).

2. layout.tsx: Changed appleWebApp.statusBarStyle from "default" to
   "black-translucent" — the only mode that gives true fullscreen on
   iOS. Content extends under the status bar, and we use
   env(safe-area-inset-top) padding on all fixed/sticky headers to
   keep content visible.

3. (auth)/layout.tsx: Added env(safe-area-inset-top) padding to the
   root container and env(safe-area-inset-bottom) to the centered
   content wrapper. The Back button was hidden under the notch.

4. page.tsx (marketing): Added env(safe-area-inset-top) padding to the
   fixed nav header and env(safe-area-inset-bottom) to the footer.

5. admin/page.tsx: Added env(safe-area-inset-top) to the mobile top bar
   and safe-area insets to the mobile sidebar drawer.

The app layout's mobile top bar and bottom nav already had correct
safe-area insets — no changes needed there.
