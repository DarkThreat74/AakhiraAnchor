Offline-first PWA: instant loads from IndexedDB, sync when online

ARCHITECTURE:
- Added Dexie.js IndexedDB database (src/lib/offline/db.ts) as the client-side
  source of truth for all app data (events, prayer times, prayer logs, sunnah
  logs, analytics, friends, qadaa, goals)
- Created useLocalData hook (src/lib/offline/useLocalData.ts) implementing the
  local-first pattern: read from IndexedDB instantly → fetch from API in
  background → update IndexedDB + React state
- Added localStorage cache for prayer settings (timezone, madhab, calc method)
  so the app never needs a network round-trip for timezone

INSTANT LOADS (NO SPINNER):
- DayViewClient: reads cached events, prayer times, prayer logs from IndexedDB
  on mount → renders immediately. API fetch happens in background and updates
  state + IndexedDB when it returns. Spinner only shows on first-ever visit.
- MonthViewClient: same pattern — reads cached events + prayer logs for the
  entire month from IndexedDB instantly, fetches fresh data in background.
- PrayerDashboardClient: reads cached analytics, friends, qadaa, today's logs,
  sunnahs, and prayer times from IndexedDB instantly. 7 API calls happen in
  background and update both state and cache.
- GoalsClient: caches goals in IndexedDB on mount, updates cache on sync.

iOS SAFARI FALLBACK:
- Background Sync API is not supported on iOS Safari. Added visibilitychange
  listener in sw-register.tsx that triggers outbox sync when the app becomes
  visible and online — catches cases where the user came back online while
  the app was in the background.
- Also syncs on initial load if online (catches app reopen while online).

SERVICE WORKER IMPROVEMENTS:
- Bumped cache version to waqt-v19
- Added navigation preload support for faster page loads
- Added /offline.html to precache URLs

SECURITY:
- Clear all IndexedDB offline cache + localStorage prayer settings on logout
  to prevent cross-user data leakage on shared devices
