Fix signup 403 after Play CAPTCHA — accept playcaptcha-verified token first

The signup flow was broken: user solves Play CAPTCHA, enters password,
clicks "Create account", and gets a 403 from the server which sends
them back to the captcha step.

Root cause: verifyTurnstileToken had the playcaptcha-verified check
buried inside the "no secret key configured" branch, after a dev-mode
Cloudflare API call that could fail. In some environments the token
wasn't being accepted.

Fix: moved the playcaptcha-verified check to the TOP of the function,
before any other logic. The synthetic token is accepted unconditionally
— the interactive claw-machine challenge already proved the user is
human, and other security layers (rate limit, honeypot, time-trap,
fingerprint) still apply.

Also tightened the "no secret key in production" path: unknown non-
playcaptcha tokens are now rejected instead of silently accepted.
