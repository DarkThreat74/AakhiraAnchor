Fix false "Set your location" notification when location is set

The calendar day view showed "Set your location in Settings" even
when the user's location was already configured. This happened
because the message showed whenever prayerTimes was null and
loading was false — but prayerTimes can be null for several
reasons that have nothing to do with location:

  - User navigates to a date outside the cached month (sync only
    fetches the current month, so the retry still 404s)
  - Network error during prayer-times fetch
  - AlAdhan API failure during sync
  - Sync rate limit hit (5/hour)

Fix: The /api/prayer-times GET endpoint now runs the settings
lookup in parallel with the cache lookup and returns a
`locationSet` boolean in the response body (both on 404 and
success). The client tracks this flag and only shows the "Set
your location" message when locationSet is actually false.

Also: the client now only attempts the sync retry when location
is confirmed to be set, avoiding a wasted API call when the user
genuinely has no location.
