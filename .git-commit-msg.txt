Offline-first: notification scheduler reads from IndexedDB cache

The notification scheduler runs every 5 minutes and on every visibility
change, making 4+ API calls each time. When offline, it couldn't schedule
any notifications because all prayer times and events came from the API.

Updated schedulePrayerNotifications, checkMissedPrayers, and
scheduleReminderNotifications to read from the IndexedDB cache first
(works offline), falling back to the API only if the cache is empty.

This means:
- Notifications work offline using cached prayer times + events
- Fewer API calls when online (uses cache, only hits API on cache miss)
- The 5-minute re-schedule interval no longer generates 4+ network
  requests per cycle when data is already cached
