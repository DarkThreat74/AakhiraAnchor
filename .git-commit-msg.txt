Fix Goals offline support + SW improvements

Offline support for Goals:
- SW now returns synthetic goal object in offline POST response so the
  client can add it to local state immediately (with _pending flag)
- GoalsClient listens for EVENT_SYNCED message from SW and refetches
  goals to replace temp IDs with real server data
- Excluded /api/goals/share and /api/goals/shared from SW outbox
  (share management needs network, shouldn't queue offline)
- Added /goals/shared/ and /privacy and /terms to SW public page
  exclusion list (don't intercept, let browser handle normally)
- Bumped SW cache version to waqt-v16

Tested:
- Migration ran successfully against Neon (goals + goal_share_tokens)
- GET /api/goals returns empty array for new user
- POST /api/goals creates goal with correct fields
- POST /api/goals with parentId creates sub-goal (branch)
- PATCH /api/goals with status=done sets completedAt
- DELETE /api/goals?id=... cascade-deletes children
- POST /api/goals/share generates UUID token
- GET /api/goals/shared?token=... returns public goals + ownerName
- /goals page renders with "Goals" heading and "Add a goal" button
- /goals/shared/<token> page renders (200)

Also added tsx dev dependency and migration script.
