Recurring event bulk edit, expanded color palette, public color sync

Three issues fixed:

1. Edit all recurring events at once:
   - Added PATCH/DELETE /api/events/bulk endpoint that updates/deletes all
     events sharing the same recurrenceRule for the current user
   - Added "Apply changes to all events in this series" checkbox in the
     edit form (only shows when editing a recurring event)
   - Delete confirmation now offers "Delete this one" vs "Delete entire
     series" for recurring events
   - Added recurrenceRule to CalendarEvent interface so the client knows
     which events belong to a series

2. Expanded color palette from 8 to 16 visually distinct colors:
   - Added Indigo, Mustard, Magenta, Pine, Rust, Slate Blue, Plum, Olive
   - All 16 span the full hue wheel with varied saturation/lightness so
     they remain distinguishable side-by-side

3. Public calendar now shows user-chosen colors:
   - PublicCalendarClient was using getReminderColor(event.title) (a
     hash-based color) for reminders instead of event.color
   - Now passes event.color to getReminderColor so user-chosen colors
     are respected on the public shared calendar
   - Same fix applied to MonthViewClient for consistency
